# 图形界面使用手册

## 首次启动

1. 双击发布包中的可执行文件（或源码运行 `python -m jsj_desktop`）。
2. 程序自动创建本机数据目录；初始状态**没有任何内置档案、报名信息或活动链接**。
3. 窗口顶部显示按 `Asia/Shanghai` 时区实时更新的北京时间与连接状态；操作反馈以右下角浮动提示呈现。
4. 左栏（运行配置 + 报名信息）支持鼠标滚轮、触控板双指滑动、触摸屏拖动滚动，
   也可拖动该栏右侧的滚动条；右侧「实时终端」独立滚动，互不影响。

## 标准流程

### 第一步：读取本次表单

在左栏「运行配置」的链接框粘贴本次表单链接（完整 URL 或末尾 token），点 **读取表单**。

- 读取成功后会显示表单名称、状态、开放时间、验证码、字段数，并在「报名信息」页按结构生成控件。
- 若显示「启用（纯接口不可用）」，说明表单启用了验证码，请改用网页端手动填写。
- 读取失败会切换为「离线模式 · 纯文本字段」，可直接编辑已有配置；启动时脚本会再次尝试在线读取。

### 第二步：填写 / 切换报名人

在左栏下方「报名信息」区域：

- **首次使用**：按字段填写，点「保存信息」。下拉框字段会自动列出表单选项；联动隐藏的字段不会写入配置，也不会提交。
- **多人管理**：
  - 输入名称 → 「把当前信息存为新档案」；
  - 在列表中选择一套档案即**自动切换**：整批写入本任务的 `报名信息.json` 并更新界面；
  - 「更新选中的档案」把界面当前内容写回该档案；「重命名」「删除」按需使用；
  - 「导出档案」「导入档案」用于备份/换机，文件由用户自己选位置；
  - 菜单「文件 → 导入旧版数据…」可一次性导入旧脚本文件夹里的全部数据。

### 第三步：确认参数与演练

回到左栏「运行配置」：

| 参数 | 说明 | 默认 |
|---|---|---|
| 快速模式 `--quick` | 不问时间来源、直接用表单时间与默认冲刺参数 | 关 |
| 仅演练 `--dry-run` | 只生成 `entryAttributes`，不发送任何提交请求 | 关 |
| 自动应答缺项 | 缺项时沿用配置值、不弹窗；关闭则由弹窗询问 | 开 |
| 逐项确认信息 | 启动时逐项复核全部字段 | 关 |
| 开放时间来源 | 1 表单时间 / 2 手动指定 / 3 不等待立即提交 | 1 |
| 手动时间 | 北京时间 `YYYY-MM-DD HH:MM:SS` | 空 |
| 提前量(秒) | 负数＝开放后再起跑，正数＝提前冲 | `-6` |
| 间隔(秒) | 两次提交间隔；过小易被风控 | `0.05` |
| 时长(秒) | 开放后最长冲刺时间 | `40` |

建议先点 **演练自检**：在右侧「实时终端」看到 `[dry-run] 最终 entryAttributes = …`；如需查看「本次将提交的信息」预览表，用菜单「任务 → 预览提交数据…」。

### 第四步：启动与观察

点 **启动脚本**，在右侧「实时终端」观察：

- 「等待开放」阶段按距离开放的时间打印心跳；状态卡显示倒计时。
- 进入冲刺后按「第 N 次：未开放 / 网络异常 / ✅ 提交成功」实时刷新。
- 成功后自动停止（`entryToken` 或重复提交保护），不会重复提交。
- 超时会提示手动打开表单填写。
- 需要中止点 **停止**；多任务可用菜单「任务 → 停止全部任务」。

## 多人 / 多开任务

点顶部 **+ 新建任务**（最多 8 个）：

- 每个任务有独立的报名信息文件、表单链接、时间参数、日志与档案选择；
- 切换任务标签时界面状态互不干扰；
- 新任务默认继承主任务的报名信息，可立即切换为另一套档案；
- 「关闭当前」需先停止该任务；配置目录会保留、不会删除数据。

> 想给不同任务设不同时间时，请勿勾选 `--quick`（它会跳过时间询问并统一使用表单时间与默认参数）。

## 主题与视觉

菜单 **帮助 → 设置与关于… → 高级选项** 提供三个主题状态。

- **黑色** 使用深色玻璃质感表面和青绿色主操作色，适合夜间运行。
- **白色** 使用浅色工作区和轻薄描边，成功、警告、失败颜色保持原有语义。
- **跟随系统** 读取当前系统外观，系统切换时更新主窗口、菜单、日志和弹窗。

主题选择写入本机 `settings.json` 的 `theme_mode`，切换主题不会重建任务、清空日志或修改报名数据。

## 检查更新与升级（1.3.0）

菜单 **帮助 → 检查更新与升级…** 打开独立弹窗，显示**当前版本**、**最新版本**、
适用平台、更新通道与版本说明。点「检查更新」重新联网查询；发现新版本后点
「立即更新到 vX」即可依次完成下载、`SHA256SUMS.txt` 校验、安装与自动重启。

- 升级只替换程序文件：`报名信息.json`、`profiles.json`、任务目录与日志都不读写，
  旧版本会先备份；任一步失败都会弹窗说明原因并保留当前版本。
- 有任务正在运行时会拒绝升级，请先点「停止」结束全部任务。
- macOS：备份旧 `.app` 后替换、重做 ad-hoc 签名、去除隔离属性再重启；
  Windows：暂存新目录，程序退出后由独立 PowerShell 进程完成替换、回滚并自动启动；
  源码运行：切换到 `<数据目录>/updates/<版本>/` 并启动新版。
- 启动时默认在后台检查新版本。在线检查发现新版本后，点击主窗口顶部的按钮可打开
  对应版本的 GitHub 发布页。可在「帮助 → 设置与关于」关闭启动检查。
- 「复制下载链接」可把当前平台安装包地址复制到剪贴板，供手动下载。

**从 1.0.0 / 1.0.1 / 1.0.2 / 1.0.3 升级**：这些版本的修复包会随本次覆盖发布
同一套更新入口。若仍使用旧冻结包，请下载 Release 资产
`JinshujuDesktop-Upgrade-Helper.py`，用本机 Python 运行
`python JinshujuDesktop-Upgrade-Helper.py --upgrade`（先可用 `--check` 只查看版本），
或直接下载对应平台的目标版本安装包覆盖安装。Windows 原位修复前请退出旧程序，
四个历史版本与 1.3.0 共用同一用户数据目录与配置格式，升级后档案、报名信息与上次链接均原样保留。

命令行等价入口：

```bash
python -m jsj_desktop --check-update     # 只读显示当前/最新版本
python -m jsj_desktop --apply-update     # 校验后安装并切换到最新版
```

## 日志与隐私

- 「实时终端」支持自动滚动、清空、导出为 txt、快捷应答按钮与手动输入行。
- 在「帮助 → 设置与关于」勾选「日志脱敏显示」可隐藏手机号与长数字（**只影响显示，不影响提交数据**）。
- 日志默认仅在内存；导出文件可能含报名信息，请自行妥善保管。

## 常见问题

| 现象 | 处理 |
|---|---|
| 启动即提示「尚未设置表单链接」 | 在控制台填写链接并保存，或从旧版导入 |
| 报「字段【X】未选择有效选项」 | 点「读取表单」刷新选项后重新选择；换活动后旧选项会失效 |
| 报「为必填项但内容为空」 | 在报名信息页补齐必填（`*` 标记）字段 |
| 提示「表单启用了验证码」 | 纯接口提交不可用，请网页端手动填写 |
| 弹窗要求补充信息 | 关闭「自动应答缺项」后属于正常交互；也可在「实时终端」的手动输入行应答 |
| 窗口打不开 / 报 tkinter 缺失 | 使用官方 Python 安装包并勾选 Tcl/Tk；或临时用 `--cli` |
| macOS 上「读取表单」失败、提示 `CERTIFICATE_VERIFY_FAILED` | 1.0.2 起已随包携带 CA 根证书；可命令行运行 `JinshujuDesktop.app/Contents/MacOS/JinshujuDesktop --check-tls` 诊断，并检查系统时间与网络代理 |
| macOS 双击提示「应用程序 "JinshujuDesktop.app" 无法打开」，但再解压 / 复制一次就正常 | 不是软件损坏：下载的 `.app` 带隔离属性会从随机只读路径运行，若目录在 iCloud 桌面且同步未完成（截图提示「iCloud 储存空间已满」、文件名带云朵图标），bundle 内文件尚未落地。1.0.3 起请用 `.dmg` 拖入「应用程序」；或把 zip 解压到本机「下载」、等同步完成、把 `.app` 拖到本地目录后打开；必要时 `xattr -dr com.apple.quarantine /Applications/JinshujuDesktop.app` |
| 检查更新提示「无法获取最新版本信息」 | 检查网络、代理与系统时间；GitHub 匿名接口可能限流，程序会自动切换其它通道。仍失败时可用「复制下载链接」手动下载，当前版本不受影响 |
| 更新提示「SHA256 校验失败」 | 多为下载不完整或代理/缓存篡改，已删除临时文件并取消安装；重试或从 Releases 页面手动下载 |
| 更新提示「版本/平台不匹配」 | 缓存可能指向旧版本或其它架构的包，已阻止安装；重新下载对应系统的 1.3.0 包 |
| 1.0.x 旧版本里找不到「检查更新」菜单 | 仍在使用旧冻结包时，用 Release 的 `JinshujuDesktop-Upgrade-Helper.py`；覆盖发布后的对应安装包包含统一更新入口 |
