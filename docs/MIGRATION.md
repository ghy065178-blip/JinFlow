# 从旧版脚本迁移

旧版目录保持原样、不会被修改；迁移只是**复制**数据到新的用户数据目录。

## 旧 → 新 对应关系

| 旧文件 | 新位置 | 处理方式 |
|---|---|---|
| `报名信息.json` | `<数据目录>/tasks/t1/报名信息.json` | 原样保留「按字段中文标签」格式与 `表单链接` |
| `报名信息.backup.json` | `<数据目录>/tasks/t1/报名信息.backup.json` | 可选复制；新程序写入时会自动生成备份 |
| `个人档案.json` | `<数据目录>/profiles.json` | 结构兼容，直接导入并保留 `active` |
| `多开任务/task_t2/报名信息.json` 等 | 每目录转成一套档案 | 以「姓名」或目录名命名；也可按任务分别导入 |
| `panel_url.txt` | — | 不再需要（无本地 HTTP 服务） |
| `启动可视化控制面板.bat` / `启动终端自动提交.bat` | 可执行文件或 `python -m jsj_desktop` | 不再需要 |
| `field_rules.json` / `form_structure.json` / `金数据表单字段分析.html` | — | 真实活动分析产物，不迁移；程序运行时在线拉取结构 |
| 内置 `DEFAULT_TOKEN` | — | 不再内置；首次在控制台填写链接，之后本地记住 |

## 方式一：图形界面（推荐）

菜单 **文件 → 导入旧版数据…**，选择旧脚本所在文件夹，程序会：

1. 读取根目录 `报名信息.json` → 写入当前任务配置；
2. 读取根目录 `个人档案.json` → 合并进档案库（id 重复会生成新 id，不覆盖）；
3. 遍历 `多开任务/*/报名信息.json` → 每个目录生成一套档案。

导入完成后自动刷新档案列表与报名信息字段。

## 方式二：命令行

```bash
python tools/migrate_legacy.py --source "D:/path/to/旧脚本文件夹"
# 可指定目标数据目录
python tools/migrate_legacy.py --source "D:/path/to/旧脚本文件夹" --data-dir "D:/my-data"
```

## 方式三：手工复制

按上表把文件复制到「帮助 → 设置与关于」窗口显示的数据目录即可；文件名与 JSON 结构完全兼容。

## 桌面版内部升级（1.0.x → 1.2.0）

这与上面的「旧脚本数据迁移」是两件事：**桌面版 1.0.0 / 1.0.1 / 1.0.2 /
1.0.3 与 1.2.0 共用同一用户数据目录、同一份 `报名信息.json` 与
`profiles.json` 格式**，升级不需要也不执行任何数据迁移。

| 当前状态 | 升级方式 |
|---|---|
| 已是 1.2.0 | 「帮助 → 检查更新与升级…」直接检查并升级后续版本 |
| 1.0.x 源码运行 | `python -m jsj_desktop --apply-update` 或应用内菜单；也可直接拉取新源码 |
| 1.0.x 冻结包（无更新代码） | 下载 Release 资产 `JinshujuDesktop-Upgrade-Helper.py`，执行 `python JinshujuDesktop-Upgrade-Helper.py --upgrade`；或直接下载对应平台 1.2.0 安装包覆盖 |

升级过程只写临时目录、安装位置与 `<数据目录>/updates/`，旧安装会备份；
`报名信息.json`、档案、任务目录、上次表单链接均原样保留。升级后建议按下面
清单复核一次表单选项（换活动时旧选项编码会失效，与升级本身无关）。

## 迁移后检查清单

- [ ] 在左栏「运行配置」确认表单链接仍是本次活动的链接（旧链接可能已失效）。
- [ ] 点「读取表单」，确认字段与选项已更新；换活动后旧选项编码会失效，需重新选择。
- [ ] 在左栏「报名信息」检查每套档案是否齐全、姓名是否匹配。
- [ ] 先用 **演练自检**，核对「本次将提交的信息」预览与日志中的 `entryAttributes`。
- [ ] 确认旧目录中的个人信息已按需要妥善保管或删除（本项目不会动它）。
