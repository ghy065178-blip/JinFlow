# 1.3.0 玻璃质感界面与方案 B 图标设计规格

## 目标

在保持 1.2.0 主窗口结构、布局层级、组件位置和业务流程的基础上，完成方案 B 应用图标、统一的玻璃质感视觉增强、黑色主题、白色主题和跟随系统主题控制，并确保顶部现有北京时间区域按真实的 Asia/Shanghai 时区持续更新。

本次范围只涉及界面表现、主题状态、图标资源和时间显示可靠性。表单解析、联动规则、报名信息格式、提交请求、任务并发、更新流程和数据目录行为保持原有接口与结果。

## 现状基线

- 主窗口由 header、多开任务栏、五张状态卡、左侧滚动区域和右侧实时终端组成。
- `MainWindow` 已在 header 中创建北京时间标签，并在 `_poll` 中按秒刷新。
- 当前时间实现使用固定 UTC+8 时区对象，文案和显示区域已经存在，缺少显式的 `Asia/Shanghai` 语义与主题化刷新测试。
- `theme.py` 只有一套深色调色板，设置窗口没有主题选择。
- 打包脚本已经支持 `packaging/icons/app.icns` 和 `packaging/icons/app.ico`，缺少实际图标文件。

## 方案 B 图标

图标以叠放档案卡和中心连接节点为核心，表达多人档案、任务切换、表单字段联动和集中管理。主色使用深蓝、靛紫和柔和玫红渐变，前景保留白色节点与细线，保证 Dock、任务栏和文件列表中的缩小识别度。

资源约定如下。

- `packaging/icons/app.svg` 保存可编辑矢量源稿，作为设计追溯文件。
- `packaging/icons/app.icns` 提供 macOS 多尺寸资源。
- `packaging/icons/app.ico` 提供 Windows 16、32、48、256 尺寸资源。
- 图标不包含真实个人信息、表单 token 或第三方品牌标识。

## 玻璃质感实现

项目运行时保持 Python 标准库和 tkinter/ttk 约束。Tk 在四个平台上没有统一的系统级 backdrop blur API，因此采用跨平台的组合式玻璃表现。

- 背景使用低饱和渐变层和轻微明暗分区，模拟柔和的环境光。
- 面板、任务栏、状态卡和弹窗使用低对比度表面色、轻薄描边和内侧高光。
- 通过现有的嵌套 Frame、`highlightbackground`、`borderwidth`、padding 和 ttk style 状态实现柔和阴影层次。
- 日志区域保留更高的不透明度和单色等宽字体，避免玻璃效果降低日志辨识度。
- 输入框、下拉框、复选框、按钮和危险操作保留清晰的焦点、悬停、禁用和错误状态。
- 不使用全窗口透明度，避免文字、弹窗和跨平台输入控件整体变灰。

颜色会集中在 `theme.py` 的主题令牌中。深色主题继续保留原有青绿色、蓝色、绿色、琥珀色、红色和紫色语义色。白色主题只替换背景、表面、边框和文本层级，状态颜色保持相同含义。

## 主题模式

`settings.json` 新增 `theme_mode`，可取 `dark`、`light`、`system`，默认值为 `system`。旧配置没有该字段时自动使用默认值。

主题控制放在现有“帮助 → 设置与关于”窗口的高级选项区域，不改变主窗口组件位置。控件使用三个互斥选项，并明确显示当前选中状态。

- 黑色主题直接应用深色令牌。
- 白色主题直接应用浅色令牌。
- 跟随系统在 macOS 上读取系统外观，在 Windows 上读取系统应用主题设置，其他平台采用浅色回退并保持可手动切换。

切换主题时更新根窗口、主窗口控件、菜单、toast、提交预览、设置窗口和更新弹窗。切换不会重建任务、清空日志或修改报名数据。系统模式定时检查系统外观变化，检测到变化后更新一次界面令牌。

## 北京时间

继续复用现有 header 时钟区域，不新增卡片、不改变布局。界面时钟使用 `ZoneInfo("Asia/Shanghai")`，缺少系统时区数据库时回退到固定 UTC+8。`MainWindow._poll` 保持现有 100 ms 事件循环，只在秒值变化时更新 `clock_var`，显示格式保持 `HH:MM:SS`。

手动开放时间解析、倒计时、引擎日志和提交流程统一复用同一时区常量，避免界面显示和业务等待使用不同时间基准。新增测试会覆盖时区对象、格式和连续刷新逻辑。

## 验证标准

- 既有 UI parity、滚动、数据、引擎和更新测试继续通过。
- 新增主题默认值、旧配置兼容、三种模式切换和主题令牌测试。
- 新增北京时间时区和显示格式测试。
- 静态检查确认主窗口仍包含 header、taskbar、cards、left scroll、terminal 和 toast 六个布局区域。
- 图标文件通过打包脚本的路径检查，Windows 和 macOS 构建仍使用各自的图标入口。
- 在无法绑定本地测试端口的受限环境中，端到端更新测试需要单独记录环境限制，不能把该限制归因于本次 UI 改动。

## 明确不在范围内

- 不重排主窗口区域，不改动组件位置，不引入标签页或浏览器窗口。
- 不改变表单请求、提交节奏、任务数量、数据文件格式和更新协议。
- 不添加第三方运行时依赖，不引入 Qt、Electron 或平台专属 UI 框架。
