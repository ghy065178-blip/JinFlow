# JinFlow 2.0.0 UI、窗口过渡与发布修订设计

## 目标

在保留 JinFlow 现有报名流程、任务管理、数据格式和四平台打包入口的前提下，完成左栏滚动与可调分栏、档案按钮布局、高清 Logo、液态玻璃视觉迭代、Windows 窗口过渡稳定性和应用内更新入口改造。应用版本继续显示 `2.0.0`，通过发布修订号让已经安装旧 `2.0.0` 包的用户也能识别本次替换发布。

## 已确认的约束

- 目标发布平台为 Intel Mac、Apple Silicon Mac、Windows x86_64 和 Windows ARM64。
- 主窗口仍使用 tkinter/ttk。HTML 文件和设计规范提供视觉参考，不直接替换原生窗口实现。
- header、任务栏、状态卡、左栏报名信息、右侧实时终端、菜单和现有交互入口继续保留。
- 表单读取、联动显隐、报名信息存储、个人档案操作、任务运行和更新安装器的业务语义不变。
- 顶部“更新”按钮只在确认有新版本或更高发布修订时显示。按钮打开更新面板，用户在面板中确认后才下载和安装。
- 发布动作覆盖现有 GitHub `v2.0.0` release 的同名 tag 和资产，并在更新栏目中说明相对上一代 `2.0.0` 的更新、新增、修改、兼容性和验证结果。

## 方案与取舍

采用增量改造现有 tkinter/ttk 实现。该方案只触碰现有滚动容器、主窗口布局、主题令牌、更新通道和窗口事件处理，能继续复用任务线程、个人档案、更新校验、安装回滚和四平台构建。迁移到 Electron 或按平台重写 UI 会破坏已验证的入口和打包链，因此不纳入本次范围。

## 设计

### 左栏滚动与可调分栏

`MainWindow._build_main` 使用横向 `PanedWindow` 承载左栏和实时终端。左栏默认宽度接近现有 420 像素，设置左栏和右栏最小宽度，用户可拖动中间分隔线扩大或缩小左侧区域。左栏内部仍由 `ScrollableFrame` 提供滚动条、滚轮、触控板和触摸拖拽。

`ScrollableFrame` 用像素增量和事件合并处理滚轮。Windows/macOS 普通滚轮提供正常页面速度，触控板的小增量保持细粒度移动，触摸拖拽使用 Canvas 的像素平移。滚动区域更新通过一个空闲回调合并，动态字段重建只触发一次布局重算。事件只绑定在左栏子树，不影响右侧终端输入和日志滚动。

### 档案按钮布局

个人档案下拉框单独占一行。应用、更新、重命名、删除按钮放在下一行的等宽网格中，删除按钮固定在最右侧。按钮行随左栏宽度重新布局并保留最小可点击尺寸，避免下拉框和按钮在高 DPI、窄窗口或不同系统字体下互相挤压。

### 高清 Logo 与视觉风格

使用 `packaging/icons/app.svg` 导出 1,024 × 1,024 像素的 PNG 母图和预先抗锯齿缩放的顶栏资源。主窗口按显示缩放选择 48、72 或 96 像素图标，macOS 和 Windows 图标从同一母图导出。

视觉令牌沿用设计文件中的深色底、Cyan/Purple/Emerald 极光色、半透明层、轻薄白边、顶部 specular 高光和柔和阴影。Tk 不支持网页的 `backdrop-filter`，实现使用现有 `theme.py` 的跨平台色阶和 PNG 表面模拟。主题切换只更新令牌和控件颜色，不重建任务或改变报名流程。

### Windows 窗口过渡

Windows 主窗口监听根窗口的 `<Configure>`，按尺寸变化合并状态刷新。左栏每 16 毫秒最多提交一次 Canvas 宽度更新，滚动范围变化后再更新滚动条。尺寸稳定后补一次任务标签和状态卡刷新。

该流程不使用透明度闪烁、销毁重建窗口或阻塞式 `update()`。它只改变重排时机，保留原有控件对象和焦点。Windows 特有的切换视觉效果需要在 Windows CI/实机中验证，macOS 本地验证覆盖同一事件合并逻辑和交互行为。

### 更新清单与发布修订

产品版本与标签继续为 `2.0.0` 与 `v2.0.0`。原 2.0.0 客户端只比较数字版本，公开清单和安装包首行标记因此使用 `2.0.0.1`。新版客户端验证标签、构建和 `release_revision` 一致，并显示 `2.0.0` 与修订号。

启动后台检查复用现有多通道探测、平台资产选择、SHA256 校验和安装回滚。顶部按钮只由通过版本、tag 和修订校验的结果驱动。按钮点击打开 `UpdateDialog`。更新面板通过队列在主线程显示检查中、下载中、校验中、解包中、安装中、成功和失败状态。

## 测试策略

按测试驱动开发执行，每个行为先增加会失败的测试，再写最小实现。

- 滚动测试覆盖普通滚轮速度、触控板小增量、触摸像素拖拽、边界和左栏事件隔离。
- 布局测试覆盖 `PanedWindow` 分栏、按钮行等宽网格和最小宽度约束。
- Logo 测试覆盖运行时 PNG 尺寸、缩放加载和四平台打包资源路径。
- 窗口测试覆盖连续 Configure 合并、过渡期间跳过重绘、稳定后只刷新一次和销毁时取消定时器。
- 更新测试覆盖同版本更高修订显示按钮、相同修订隐藏按钮、顶部按钮打开更新面板、下载/安装状态和失败反馈。
- 完成聚焦测试后运行全量 `unittest`、`--self-test`、`check_no_pii.py --strict`、`check_update_channel.py --offline`、`git diff --check` 和构建元数据检查。

## 验证边界

本地 macOS 可以验证 UI、滚动、按钮可点击区域、更新结果处理和发布清单逻辑。Windows 窗口模式的实际闪烁只能在 Windows runner 或真实 Windows 设备上观察，因此发布前报告会区分代码路径验证与 Windows 实机视觉验证。
